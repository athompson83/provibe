# Blueprint Studio

## Goal
Turn a new, existing, stalled or launch-prep project into a constrained canonical model and build package while challenging avoidable complexity.

## Entry modes
Start, Import, Rescue, Prepare for Launch.

## Adaptive interview
Question selection is conditional and prioritized, not a 70-question static wizard. Domains: problem/user/outcome, buyer/pricing/distribution, MVP scope/exclusions, roles/permissions, workflows, platform, data, integrations, security/compliance, design, operations, builder constraints and launch.

## Challenge engine
Flag missing buyer/outcome, unsupported API assumptions, premature native mobile, regulated/high-liability scope, excessive MVP, weak validation and dependency uncertainty. The system may recommend validation before build.

## Reference workflow
Upload screenshots/sketches and annotate what is useful: layout, navigation, typography, density, interaction, color, components and overall feel. Do not indiscriminately clone another product.

## Outputs
Canonical revision; product brief/PRD/MVP scope; architecture/security/data contracts; design direction/tokens; 3–5 key screen specs including loading/empty/error/unauthorized/partial/success states; roadmap; risks; setup guidance; tool-specific JSON prompt package.

## Rescue output
Repository/current-state summary, contradictions/missing docs, blockers/open questions, evidence coverage and recommended recovery sequence.
