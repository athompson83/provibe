# Build Control Center

## Goal
Create recurring value by telling owners what is true, what requires attention and what should happen next.

## Portfolio
Project, stage, health/readiness, latest verified activity, provider freshness and next action. Avoid superficial project-management task density.

## Build Cockpit must answer
1. What is actually complete?
2. What is currently being worked on?
3. What is blocked?
4. What requires the owner’s decision?
5. What should happen next?

## Project workspace
Overview, Blueprint, Code, Database, Deployments, Changes, Ask, plus later Decisions, Progress Reports, Prompt History, Risks, Readiness, ETA/Costs, Integrations and Evidence.

## Verdicts
`ready | ready_with_accepted_risks | not_ready | blocked | conflicting_evidence | insufficient_evidence`.

Verdicts list contributing evidence and required controls. They are not sentiment scores.

## Owner decisions
First-class records with decision area, options/context, chosen outcome, project revision, affected artifacts, risk acceptance and timestamp. Decisions never disappear into chat history.
