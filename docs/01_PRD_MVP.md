# PRD & MVP Requirements

## Product definition
A SaaS project control plane for nontechnical and semi-technical software owners combining project definition, connected application intelligence, evidence-backed coding-agent oversight, persistent project memory, and launch-readiness guidance.

## Golden path
GitHub Cloud + Vercel + Supabase + Next.js/TypeScript/JavaScript + Codex/Claude Code/Cursor. Provider integrations are read-only in MVP.

## Entry modes
1. Start a new app.
2. Import an existing app.
3. Rescue a stalled app.
4. Prepare an app for launch.

## Revenue-validation wedge
- Adaptive founder interview with scope/business/API/compliance challenge logic.
- Canonical structured project model.
- Relevant artifact generation only.
- Design-reference upload/annotation and 3–5 key screen specifications.
- Versioned JSON prompt adapters for Codex, Claude Code, Cursor.
- Existing-project import/rescue.
- GitHub observation of branches/commits/PRs/checks.
- Vercel deployment observation/reconciliation.
- Paste/upload agent progress reports.
- Atomic claim extraction + evidence classification.
- Build Cockpit verdict, blockers, owner decisions, and next prompt.

## Connected MVP completion
Add Supabase OAuth/metadata/advisors, TypeScript/Next.js deterministic analyzer, code↔database relationships, deployment error translation, application map, grounded Ask My App, readiness framework, retention/deletion controls, billing and usage limits.

## Explicit MVP exclusions
No autonomous code changes, merges, deployments, migration execution, production database writes/row browsing, full IDE, every programming language/provider, penetration-test certification, app-store submission, or in-product coding-agent runtime.

## Evidence states
`reported | observed | verified | contradicted | unknown | blocked | accepted_risk`

“Verified” requires evidence. Missing capability/data is never equivalent to healthy state.

## Success criteria
- New or rescued project reaches an understandable current-state report quickly.
- Material agent claims can be traced to evidence or explicit unknowns.
- User can identify current production commit and major blockers without provider-console expertise.
- Returning users review changes/verdicts/prompts after agent or deployment activity.
- Paid retention is driven by monitoring/verification, not one-time document generation.

## Release gates
### MVP
Tenant isolation, secure read-only provider connection patterns, canonical revisioning, evidence provenance, GitHub/Vercel progress verification, polished golden-path UX.

### Beta
Supabase integration, AST graph, grounded explanations, usage/billing, deletion/export, monitoring and evaluation suite.

### Production
Multi-provider/language expansion only after accuracy evidence; SSO/audit/retention options; regional/private processing as required; formal operational/security readiness.
